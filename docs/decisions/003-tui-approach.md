# 003：TUI 采用自绘最小实现而非第三方库

- 状态：已接受（2026-11-01，见决策人栏）。
- 日期与关联任务：2026-10-31；[007：mini-agent 第一版技术方案](../design/007-agent-v1.md)。
- 决策人或审批依据：维护者 2026-11-01 指示"开始第一步的开发"，据其批准按本 ADR 建议方案实施；未单独逐条批复。

## 背景

v1 需要 TUI 完成"多轮对话 + 流式显示 + 干净退出"。候选：引入 FTXUI 等布局/组件库，或基于 POSIX termios + ANSI 转义自绘最小界面。约束：启动快速优先、不无故新增依赖、Linux 平台。

## 备选方案

- 方案 A（自绘最小 TUI）：零依赖、启动路径最短、体积最小；代价是行编辑、终端能力、resize 处理自行实现，长期功能扩展（高亮、鼠标、多面板）成本高。
- 方案 B（FTXUI）：组件与布局成熟、开发效率高；引入外部依赖（许可证需核实）、增加体积，且其渲染循环与流式 token 刷新的配合需要适配。

## 决策

建议方案 A：范围锁定为最小可用——交替屏幕、历史区 + 输入行 + 状态行、基本插入/退格/回车、Ctrl-C 中断请求、Ctrl-D 退出、termios RAII 恢复。超出此范围的界面能力一律记为 v2 需求，届时重新评估是否转投方案 B。

理由：与"轻量、快速启动"第一目标的一致性优先；v1 交互面（单栏对话）数百行自绘即可覆盖，方案 B 的主要价值（复杂布局）在 v1 用不上。

## 后果

- 收益：无新增依赖；冷启动预算可控；终端行为完全自主（异常退出恢复可测试）。
- 代价：自研行编辑仅限基本功能，宽字符/IME 支持缺失（记为已知限制）。
- 风险：ANSI 行为在不同终端模拟器上的差异——以最小特性集（不依赖鼠标/同步输出扩展）+ 人工验证常见终端缓解。
- 后续验证：人工终端验证记录（对话轮 + 异常退出后终端状态恢复检查），见设计文档第 8 节。
