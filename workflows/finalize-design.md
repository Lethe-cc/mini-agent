# 最终设计文档交付

1. 依据任务规模决定更新现有设计、新建设计，还是仅在 PR 说明文档不适用。
2. 阅读最终代码、测试、配置及实际执行结果，不能仅依赖最初方案或聊天记忆。
3. 核对模块、接口、数据模型、错误处理、发布和回滚描述；规划内容明确标注未实现。
4. 记录实际采用的外部来源、固定版本、具体章节/文件及本地差异。未访问的资料不得伪装成已核对依据。
5. 按 `templates/design.md` 更新验证表：每项验收对应证据、命令、结果及限制。未执行就写未执行。
6. 写明相对原始方案的偏差、原因、已知限制和后续工作。
7. 按需更新设计索引、架构总览和 ADR，使用链接避免重复。
8. 运行文档及项目检查。自动检查不能证明设计语义正确，仍需代码与文档一起审查。
9. 状态根据真实证据更新；没有实际人工评审，不得写人工通过。

输出：最终文档路径、关键设计变化、验证摘要、剩余风险。
