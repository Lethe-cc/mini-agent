# 缺陷修复

1. 收集复现步骤、期望行为、实际行为和受影响版本，避免记录敏感数据。
2. 阅读相关代码、测试和设计，定位原因，不仅修补表象。
3. 涉及外部依赖时按项目版本核对官方说明或指定源码。
4. 尽可能先添加能暴露问题的回归测试（分层与约定见 `docs/design/testing/`）；无法复现时明确说明证据缺口。
5. 最小范围修复，补充失败场景与兼容性验证。
6. 运行 `python scripts/check.py --require-initialized` 和相关 CTest；TUI/CLI 行为缺陷补 `tests/pty_*_smoke.py` 冒烟。如实记录结果。
7. 行为或接口变化时更新设计；小修复可仅在 PR 记录原因、验证及文档不适用说明。
8. 交付根因、修复、回归证据和剩余风险。
